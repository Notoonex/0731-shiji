# 0731 史记

把一个微信群沉淀多年的照片、视频、语音、文件和对话长期保存下来，并像苹果相册一样自动整理成可以回看的记忆。

这是一份**高保真前端原型**——设计与交互是成品，数据是假的。用来定义"自动整理之后应该长什么样"。

```bash
# 看
open index.html          # 单文件，双击即可，无需服务器

# 改
vim src/hero.html        # 改模块片段
python3 build.py         # 合并成 index.html
```

---

## 它是什么

一个八年的老友群，一万两千张照片、三万八千条消息。这些东西事实上已经丢了——不是删了，是翻不到。微信的聊天记录是一条线性的流，没有索引、没有聚合、没有人物、没有地点。

这个原型把它重新组织成：

- **首页自动策展** — 今日精选、为你回忆、最近的日子、聚会、人物、旅程、地点、名场面、媒体类型、这一年的这一天、相簿、群小传
- **图库** — 年/月/日/全部四种视图，筛选、多选、密度调节
- **群消息时间线** — 把聊天记录重排成可回看的档案，覆盖文字/九宫格/语音波形/视频/文件/链接/位置/引用/红包
- **话** — 名场面（对话片段）、群黑话词典、年度关键词、数字小传、聚会与鸽王榜
- **全屏叠层** — 回忆播放器、看图器（FLIP 转场）、导入面板、管理面板

两个只有"群聊 + 相册"合起来才成立的功能：

1. **照片 ↔ 对话双向可达**。点开一张照片，能跳到它当年被发出的那条消息，看到那天群里在说什么。
2. **鸽王榜**。从聊天记录里识别出每次聚会的应约者，再用当天有没有照片判断谁真的到场。单独的相册算不出，单独的聊天记录工具也算不出。

## 结构

```
index.html          构建产物，910KB 单文件，无外部依赖
assets/
  photos/           101 张策展照片
  people/           12 个人物头像
src/                模块片段，每个模块一组 html/css/js
  shell.*           应用外壳、路由、全局事件委托
  hero.*            首页 hero 轮播
  memories.*        为你回忆 / 最近的日子
  people.*          人物 / 旅程 / 地点
  shelf.*           媒体类型 / 这一年的这一天 / 相簿 / 群小传
  talks.*           聚会 / 名场面 / 「话」视图
  library.*         图库四视图
  messages.*        消息时间线
  overlays.*        四个全屏叠层
  login.*           账户菜单
  tokens.css        设计变量（背景 5 层 / 文本 4 级 / 圆角 6 档 / 动效曲线 4 条）
  motion.css/js     动效与光影规范
build.py            合并脚本
docs/               设计与架构文档
```

模块之间只通过 `data-*` 约定通信（`js-photo`、`js-memory`、`js-goto`、`js-gathering`…），没有跨模块的直接依赖。每个模块自带 CSS 前缀和一个 `initXxx()`。

技术上是原生 HTML + CSS + JS，零依赖、零构建工具。`build.py` 只做字符串拼接。

## 说明

- **数据是假的**。人名、群名、对话、统计数字都是为演示编的。
- **照片是占位素材**，来自 [Lorem Picsum](https://picsum.photos)（Unsplash 图库）和 [Pravatar](https://pravatar.cc)，仅用于原型演示，不可用于商业用途。真实产品里这里是用户自己的照片。
- **原型不含任何真实的微信数据处理代码**。导入面板的进度条是 `setTimeout` 模拟的。文档里描述的解密与解析方案尚未实现。
- 合规边界：这个产品的设定是处理**用户本人所在群、由群成员本人发起导入**的数据，不做批量采集、不抓取他人数据。
